# Portfolio design review checklist

## Content and hierarchy
- [ ] The hero immediately states who the person is and why the audience should care.
- [ ] The primary call to action is visible without scrolling on common desktop sizes.
- [ ] The reading order makes sense: positioning, evidence, selected work, background/process, contact.
- [ ] Project cards explain the contribution, not just the project title.

## Visual quality
- [ ] The design supports the chosen direction: clean/professional, creative/visual, or hybrid.
- [ ] Typography is readable and uses a consistent scale.
- [ ] Spacing and alignment are consistent across sections.
- [ ] Custom art is purposeful, lightweight, and does not obscure content.
- [ ] Motion is subtle, optional, and respects reduced-motion preferences.

## Responsive behavior
- [ ] Layout works at about 320px, 768px, and 1440px widths.
- [ ] Navigation, buttons, cards, and images do not overflow or become too small.
- [ ] Mobile touch targets are comfortably usable.

## Accessibility and quality
- [ ] HTML uses landmarks and one logical H1.
- [ ] All controls work with a keyboard and show focus states.
- [ ] Text/background contrast is sufficient.
- [ ] Meaningful images have accurate alt text; decorative art is hidden from assistive technology.
- [ ] Links go to the intended verified destination.
- [ ] The page has an accurate title and description.

## GitHub readiness
- [ ] Work is on a feature branch, not the default branch.
- [ ] Changed files match the approved design plan.
- [ ] No credentials, secrets, or private information are committed.
- [ ] Pull request summary identifies tests, placeholders, and follow-up work.
